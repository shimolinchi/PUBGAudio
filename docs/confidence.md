# 检测分数与置信概率（F040）

更新：2026-09-08（F040/F041）。当前模型有检测分数，尚未拟合或验收概率校准。新版离线推理已支持显式的分数、可选的校准概率，以及尚未提供的位置可信度。F041把规则接入下一版数据生成和主模型导出流程；没有改变网络、损失或正在运行的 v6 训练。

## 当前分数表示什么

| 输出 | 当前含义 | 能否直接解释成正确概率 |
|---|---|---|
| 外部 `activity_vector_norm` | 预测方向向量的长度，可超过 1；评价时同类三个轨道取最大值作为存在分数 | 不能；例如 0.8 不等于 80% 正确 |
| 旧 `self_probabilities` | 自身分类头的 sigmoid 输出，范围 0–1 | 未经校准，不能保证数值与实际命中比例一致 |
| 方位、距离 | 每个原始轨道的位置点估计 | 没有角度/距离置信区间；声音存在的概率不代表位置正确 |

模型没有在每次输出时保证 100% 确定。原有固定 0.5 门限只是把连续分数变成检出/未检出，不能代替校准。外部是“非本人来源”，不表示已判断敌友。多个声音可以同时存在，因此各类别概率不必相加为 1。

## 为什么正确的标签仍能训练置信度

即使所有标签都正确，也不代表模型能从混合音频中恢复全部事实。生成器知道声源和完整配方，模型只能观察有限窗口内的声音特征；弱声、相似音色、混音以及尚未学好的特征都会影响判断。

标签仍是“有=1、无=0”，不需要人为标注“这个样本70%有脚步”。训练产生连续分数：自身头使用二元交叉熵训练 logit，推理再取 sigmoid；当前外部头学习方向向量及其活动模长，并非独立的概率分类头。硬标签监督不强制有限训练后的预测全部为0或1。

校准时固定模型，用验证标签建立“原始分数→实际存在比例”的映射。例如**仅作示意**：1000个有效帧的原始脚步分数都在0.8附近，其中650帧真实有脚步，350帧没有，则这一分数附近的存在概率应接近65%，不是80%。这些标签可以全部正确，偏差来自模型预测。程序用所有校准拟合帧学习平滑单调映射，再在其他完整场景审计。

固定输入和权重时，当前推理是确定的计算；概率描述相同条件下一批新预测的统计可靠性，不是模型随机猜测，也不是标签本身不确定。校准仍可能失效，尤其在新背景或真实游戏分布下；模型也可能高分犯错。

## 新版推理 JSON

每 100ms 添加 `external_class_predictions` 和 `self_class_predictions`，分别对应脚步、车辆、枪声。每项包含：

- `presence_score`、`score_kind`：保留原分数及其定义。外部取三个轨道向量长度的最大值，避免 ADPIT 重复轨道导致概率重复累加。
- `presence_probability`：该帧存在至少一个可听、未被屏蔽的同类来源的校准概率估计。未加载对应校准文件时为 `null`；不伪造百分比。
- `probability_status`：`not_calibrated`、`insufficient_labels` 或 `fitted_on_synthetic_validation`。最后一种只表示已在合成验证数据上拟合，不等于真实游戏校准已通过。

原 `raw_external_tracks` 和 `self_probabilities` 保留兼容；后者始终是原 sigmoid 分数，不随加载校准文件改变。每条外部原始轨道新增 `direction_confidence: null`、`distance_confidence: null`。这两个字段目前是明确的缺失标记。

校准概率属于“每帧/每类/自身或外部”，不分配给单条 ADPIT 轨道。尚未实现轨道概率、未知声音识别、时间上的事件合并，以及“方向误差小于 20°”等定位概率。低分时不能仅凭点估计给用户肯定的精确方向和距离；产品显示门限也要根据误报/漏报代价验证后选择。

## 校准流程

`tools/calibrate_presence.py` 在最终权重确定后，用对应验证集拟合每类/每角色的单调 sigmoid 映射。外部以向量模长为输入，自身以 sigmoid 分数的 logit 为输入。保留自然正负比例，不按类别重新加权；至少各 20 个有效正负帧才拟合。该数量仅是程序下限，不表示统计证据已经充分。

## F041：数据生成与后续训练的执行规则

下一版 `configs/dataset_v6_1.json` 引用 `configs/confidence_v1.json`。这是置信度监督、校准和输出的机读规范，不是声音出现概率表，不改变场景密度、脚步比例、车声电平或轨迹。

| 规则 | 已接入的行为 |
|---|---|
| 真值 | 仍为0/1；100ms外部目标为 `counts > 0`，自身为 `self_target > 0`；沿用现有多源标签，无需额外伪造概率标签 |
| 有效监督 | 外部 `mask > 0`、自身 `self_mask > 0`；已被mask屏蔽的遮蔽/边界帧不统计；声学活动为0且mask有效的帧仍为负例，可听定义沿用现有标签 |
| 元数据 | 生成时把已解析规则写入 `training_targets.json`，与 `generation_identity.json` 一起冻结；生成器快照包含规则校验代码 |
| 校准场景 | 完整验证场景按固定种子2026090811随机分成50%拟合、50%审计；保存 `calibration_plan.json`，绑定验证清单和规则哈希，不读取测试标签 |
| 数量 | 验证至少4个场景，拟合/审计至少各2场景；每类每角色拟合至少20个有效正帧和20个有效负帧，不足则概率 `null`、状态 `insufficient_labels` |
| 统计比例 | 使用所有有效帧，不平衡采样正负例、不按分数挑选审计帧；长场景的帧数自然更多。50/50是校准场景划分，不是声音出现率 |
| 输出 | 每帧每类同时保留原始分数和校准概率；概率仅表示至少有一个该类、该角色的可听声音，位置可信度仍未实现 |

`generate_light_dataset.py` 在写出完整清单后生成校准计划；`--plan-only` 只保存规则，不提前声称校准场景已生成。`verify_light_dataset.py` 检查规则与生成身份一致、计划完整/互斥及清单哈希；改过规则或场景清单必须使用新数据版本，不能继续用旧验证记录。

未来对含本规则的数据调用新版 `tools/run_spatial_training.py` 时，会冻结校准代码，在三个预定模型导出后，自动针对主模型 `model_localization.pt` 拟合 `presence_calibration.json`，并在 CPU 推理检查中加载它。校准审计结果保存在该 JSON 中；当前只自动处理主模型，其他导出需各自校准。主模型仍按原来的验证定位F1选择，校准不修改权重或选轮规则，也不使用测试结果选校准参数。完成状态只说明流程通过，不表示实战校准或每类可靠性已验收。

现有 v6 数据没有本规则，已有400轮运行也使用旧冻结代码，因此不会被追溯修改或自动追加校准。本次仅准备规则及流程，没有重生成数据、启动新训练或拟合真实模型的概率。

### 校准审计与单独使用

验证集按完整场景随机分成校准拟合与校准审计两部分，避免同一场景相邻帧跨边界；沿用训练的遮蔽和裁剪边界 mask。审计记录 Brier 分数、10 个区间的校准误差 ECE，以及区间实际命中比例。这两个误差通常越低越好，不能仅看一个平均值，仍应检查各类的样本量和误报/漏报。

审计场景没有参与校准器拟合，但验证集曾用于模型选轮，因此不是独立的最终模型测试。脚本不读取测试标签。真实录音、实际声音比例、设备或音量分布变化后，应重新审计校准；v6.1 提高脚步比例后，也不能直接沿用 v6 的概率映射。校准不能创造模型尚未学到的区分能力，不能当作脚步漏检或方向错误已解决的证据。

校准文件绑定**确切 checkpoint 文件 SHA256**，防止另一轮权重误用。训练 checkpoint 与导出文件即使包含相同参数，文件 hash 也不同，须对实际推理使用的文件拟合。不要使用仍会被训练覆盖的 `last.pt` / `best*.pt`。当前运行的 v6 使用冻结源码，自动导出后的原有推理检查不会自动启用本次新增接口。

以下在子模块目录执行，用已冻结的最终模型和现有数据；无需重新训练骨干。命令是使用说明，本次尚未执行完整校准：

```powershell
conda activate pubg
$env:PYTHONPATH = 'src'
python tools/calibrate_presence.py --checkpoint outputs/train-spatial-v6-400epochs-20260908/model_localization.pt --dataset datasets/spatial-v6-24h-20260908 --output outputs/confidence-v6/presence-calibration.json
python -m pubg_audio.predict --checkpoint outputs/train-spatial-v6-400epochs-20260908/model_localization.pt --calibration outputs/confidence-v6/presence-calibration.json --audio datasets/spatial-v6-24h-20260908/audio/validation_0001.wav --output outputs/confidence-v6/validation_0001.json
```

可通过 `--validation-cache` 指定已有且身份校验一致的验证特征缓存，否则直接读取 WAV/标签。脚本拒绝覆盖既有校准文件，不改模型参数。

“校准概率 80%”的目标含义，是在相同评估条件下，被分到这一概率附近的一批预测中，约 80% 存在该类声音；不是对单次预测的保证，也不是模型整体 F1，更不是位置正确率。后续方向宜表达为角度误差区间，距离宜表达为距离区间，需要相应误差监督及独立覆盖率检查，不能直接复制检测概率。

方法背景：Guo 等在 [On Calibration of Modern Neural Networks（ICML 2017）](https://proceedings.mlr.press/v70/guo17a.html) 中区分原始置信分数与经验校准，并研究后处理校准方法。本实现采用单调二参数映射，效果须由本任务审计检验，不以该论文保证 PUBG 结果。
