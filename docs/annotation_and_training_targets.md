# 标注如何保存，以及怎样交给训练

2026-09-07，核对最新v5.3最终试听与当前训练加载器。原始音频/详细标签未回写；本次修正了训练裁剪的统计窗口边界。以下将已实现行为与建议字段分开说明。

## 当前每个时间步保存什么

当前是**多声源逐帧标注**。一帧可以同时有多个类别，也可以有多个同类别声源。不是给每10ms挑一个“最明显声音”，也不把混合音频标成一个类别。

原始层由两个文件组成：

| 文件 | 保存内容 | 用途 |
|---|---|---|
| `recipes.jsonl` | 声轨/角色、每次音效的起止与原声ID、枪型/材质/动作、姿态与车辆状态、曲线、投掷物等因果链、玩家视角、抽样决定 | 溯源、重放、改变任务时重新提取标签 |
| 每段的详细 `.npz` | 每声轨随时间的距离、世界/耳相对方位、坐标、速度、声学活动、可观测性、自身来源及动作状态 | 可视化、抽取不同训练目标 |

时间分辨率必须区分：轨迹步长10ms，声学标签步长也是10ms，但电平来自**32ms重叠统计窗口**，不是10ms独立波形块。60秒R04有5997个声学帧、9个声轨；`track_*`随时间数组大多为`[9,5997]`，坐标为`[9,5997,2]`。静音期间还会保存计划轨迹；必须结合事件生命周期和活动字段使用，不能仅凭有坐标就认定有声。

主要字段：

| 内容 | 当前字段 | 解释 |
|---|---|---|
| 声音类、细分类、身份 | `track_class_index / track_subtype / track_source_role` | 自身依据生成来源，不能由近距离推断 |
| 连续声轨及所属角色 | `track_id / track_actor_id` | 是片内标识；身体动作已关联原脚步人物，不是要求网络输出这些编号 |
| 距离与方向 | `track_distance_units / track_azimuth_degrees / track_direction_valid` | 方位是相对耳朵；自身方向无效，原数组的0不能解释为正前方 |
| 世界位置与玩家转头 | `track_world_xy / track_world_azimuth_degrees / listener_yaw_degrees` | 与用于定位的耳相对坐标同时保留 |
| 实际发声与可观测性 | `track_activity / track_observable / track_power` | 当前基于合成分轨电平/SIR的启发式判断，尚非人工实测可听阈值 |
| 姿态、身体动作及依据 | `track_posture / track_body_action / track_semantic_evidence` | 细姿态来自计划，共享转换原声不等于每个姿态有独有音色 |

真实例子：R04第1857个10ms声学帧，场景时间约18.58455秒，下列三声源同时活动且被当前可观测性规则接纳：

| 声轨 | 类别/状态 | 来源 | 距离（合成单位） | 相对耳朵方位 |
|---|---|---|---:|---:|
| T001 | 脚步/跑步 | 外部 | 35.10 | 328.34° |
| T004 | 脚步/跑步 | 自身 | 0，听者绑定约定 | 无效，不参与方向训练 |
| T007 | Buggy车辆/加速 | 外部 | 231.30 | 249.51° |

以上距离没有完成真实游戏米数标定。对应机读例子在`outputs/annotation-format-review-20260907/R04.frame_example.json`。

## 当前实际训练目标

训练不是把10ms音频拿出来独立识别。现有模型每次输入5秒双耳音频，特征帧步长20ms，时间池化后输出50个100ms结果。

1. `project_causal_labels.py`选择外部/自身脚步、车辆、枪声。其他声音继续留在混音里作干扰，原始详细标签不删除。
2. `dataset.aligned_targets`按100ms汇总；有声短事件取并集，位置取各声源在该窗有声帧的中位时间位置，不把两个不同声源的位置平均。
3. 生成数值张量供损失函数使用：

| 张量（单个5秒样本） | 形状 | 含义 |
|---|---|---|
| `target` | `[50,3,3,4]` | 时间×每类最多3个源×3类×`[方向x,方向y,方向z,距离/100]` |
| `counts` | `[50,3]` | 各时间步、各类别的外部活动源数量 |
| `mask` | `[50,3]` | 该时间步该类是否参与损失 |
| `self_target / self_mask` | 各`[50,3]` | 三类自身声音的多标签活动与监督掩码 |

方向用单位向量，前方为`[0,1,0]`，右方为`[1,0,0]`；不直接用角度做普通MSE，避免359°与1°的环绕问题。当前方向与距离合并在multi-ACCDDOA输出，活动由方向向量幅度编码；`counts`控制ADPIT的单源复制和多源置换。三个输出位置不是永久角色编号。

同类超过3个源时，当前屏蔽该类该窗，不无声丢弃第4个源；出现被遮蔽的目标时采用保守的类级mask。自身只训练是否发声，不回归听者绑定的0距离/无效方位。

以R04的18.5–18.6秒训练窗为例，外部脚步/车/枪的`counts=[1,1,0]`，自身活动`[1,0,0]`。可检查的当前数值目标缓存为`outputs/annotation-format-review-20260907/R04.current_targets100ms.npz`；这是格式示例，当前加载器仍按需生成目标，没有将该试听当成训练集。

这种“同一帧可出现多行声源，训练时转成多源张量”的组织与[DCASE 2024的100ms参考标注](https://dcase.community/challenge2024/task-audio-and-audiovisual-sound-event-localization-and-detection-with-source-distance-estimation#reference-labels-directions-of-arrival-and-source-distances)一致。该任务的方位正方向与本项目不同；导出兼容文件需要显式坐标转换，不能直接改列名。

## 更适合后续训练的组织方式

F041增加置信度执行规范：`confidence_v1.json`使用现有`counts > 0`/`self_target > 0`作为0/1真值，分别受`mask`/`self_mask`约束；不在NPZ中伪造“样本置信度”数组。生成器冻结规则和校准场景清单，训练导出后用验证标签拟合存在概率。它不改变本节原始10ms/训练100ms的结构，位置可信度仍未实现；见[详细规则](confidence.md)。

建议继续保留高精度原始层，正式规定“事件表＋源轨迹＋训练目标”的三层接口。训练标签步长与输入历史长度分别配置；换成过去10/20/30秒上下文，不要求把原始10ms标签改掉。

训练中间层建议一行表示一个时间窗内的一个声源，明确下列字段，再批量打包成张量：

| 字段组 | 建议明确保存 | 状态 |
|---|---|---|
| 时间 | `window_start / window_end / representative_time`及原声学统计窗口的覆盖范围 | 本次已核查并修正裁剪边界；完整显式中间格式尚未接入 |
| 身份 | `source_id / actor_id / class_id / source_role` | 原始层已有大部分；固定源ID不作为网络必须预测的目标 |
| 活动 | `emission_scheduled / acoustic_active / observable` | 必须区分计划发声、实际声学活动、遮蔽；目前“计划发声”逐帧显式字段主要覆盖脚步，其他从事件表推导 |
| 定位 | 连续耳相对方向、距离、各自有效性和标定依据 | 原始层已有几何和部分有效性；距离必须保留合成单位/估计标记 |
| 监督 | `classification_mask / direction_mask / distance_mask / self_mask` | 方向不可靠不应自动放弃类别；距离未标定不应被当成精确真实米数。逐任务/逐源损失改造尚未启用 |
| 细节 | 枪型、地面、动作、状态、依据 | 保留作按需投影和错误分析；不要要求当前三类网络输出全部细节 |

这些字段能支持论文式多源回归，也能以后生成粗距离分档目标。当前优先保持论文输出兼容，不自动切换距离损失、细分类输出或网络结构。可观测性不足、细类别不能由音频确定时，应标未知/忽略，不能把计划中存在的对象强当成声学正例。

进一步细化mask时，必须保留未知同类声源的存在，避免把它们映射成“空槽负例”；需要同时调整多源匹配/损失，不能只增加几个数组就认为完成。

## 本次已修复的具体问题

原加载器只用32ms电平窗口的中心落入哪个训练窗来选标签，没有检查整个电平窗口是否落在输入裁剪内。可复现例子：声音只出现在5.005–5.007秒，输入却截取0–5秒；旧实现仍可能给最后一个目标窗正例且参与损失。

现在检查完整电平窗口的起止。任何窗口跨越音频裁剪边界，对应100ms训练窗的外部/自身监督mask均置0；原始活动和几何保留用于审计。这样既不让裁剪外声音提供正例，也不把不完整信息强当负例。覆盖左/右边界与自身/外部的4项真实波形统计窗口回归测试通过。

这是输入裁剪边界修复，**不等于网络已成为因果模型**。当前BiGRU/注意力仍读取整个5秒，严格“只看过去”还需要把每个输出步的音频支持、目标时间约定和网络一起调整。下一版也可保存不重叠短音频块的功率，避免当前边界整窗屏蔽带来的有效监督损失。
